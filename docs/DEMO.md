# 30 秒演示：她真的记得

```bash
node demo/recall-demo.ts
```

脚本会：① 在空库上先问一遍（冷启动）→ ② 灌 20 条**虚构**记忆（横跨三周，含一条被推翻的旧决定、一笔借款的完整经过）→ ③ 用同样四个问题再问一遍。

下面是**真实输出**（不是手写的）：

```text
=== ① 空库（冷启动）===

【这时候她只能说不记得】
  · 我当初为什么决定不换工作？
      → 想不起来
  · 那次吵完之后我们是怎么说开的？
      → 想不起来
  · 我那个「每天读一小时」的计划后来怎么样了？
      → 想不起来
  · 老周那两千块还清了吗？
      → 想不起来

=== ② 灌了 20 条虚构记忆（横跨三周）===
  库里现在有 20 条事件、3 个锚点

=== ③ 同样的问题再问一遍 ===

【这次能捞到具体的】
  · 我当初为什么决定不换工作？
      → 〔4.03 分〕阿臻决定不换工作了：房贷还有两年，先熬过这段
      → 〔2.46 分〕阿臻纠结要不要换工作，主要担心新公司不稳定

      → 〔3.19 分〕阿臻定了「每天读一小时」的计划，想补一下技术
      → 〔2.29 分〕阿臻把「每天读一小时」改成了「通勤路上听一听」
      → 〔2.27 分〕「每天读一小时」头三天做到了，第四天开始断
  · 老周那两千块还清了吗？
      → 〔4.06 分〕老周把借的两千块都还清了，还请阿臻吃了顿饭
```

## 这个演示证明了什么 / 没证明什么

**证明了**：同一套检索在「没数据」和「有 20 条数据」时行为不同——空库时老实说想不起来；有数据时能命中具体那条，而且挂了锚点之后分数明显更高（换工作 2.22 → 4.03）。

**没证明**：这不是 benchmark。样本只有 20 条、问题是我写的、没有对照组。想看「比别的方案强多少」，得另做带标注的评测集。

## 自己复现

```bash
node src/cli.ts init          # 建库（会灌 17 个演示锚点）
node demo/recall-demo.ts      # 跑这个演示（用完自动删临时库）
```

数据全在 `data/demo-recall/`，跑完即删，不会碰你的 `data/memory.db`。
