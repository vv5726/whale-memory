# 从「大肥鱼 v4」能借什么（以及为什么）

> 对照对象：对方 2026-10-27 的《技术术语与概念文档 v4》。
> 逐条列出**值得借鉴 / 不值得借鉴 / 我们已经有**，每条说明为什么、怎么落地、代价多大。
> 本文只做判断，**没动代码**。

---

## 一、值得借：低成本、直接补短板（P0）

### 1. 状态去结论化（对方 §4.4）

**他们怎么做的**：原来把内部状态渲染成结论喂给模型（“你现在最想要：好奇 → 可以去读书”“现在说话应该：可以皮一点”）。
v4 改成**只喂事实**：“你在厨房；菜棚里 4 块地，土该松了；最近做过：读书；现在是 11 点。”
情绪与解读交还模型。效果：处境块 400 字 → 189 字，**每轮省一半提示词**。

**我们现在的样子**：恰好相反——提示词是高度结论式的。人格里直接写“你该怎么说话”“先理解再回”“不要演 AI 助手”。

**为什么值得借**：
这不是“学他们”，而是**和我们刚讨论的人格稀释是同一个病**：
规矩越多越淡，是因为我们把**本可以交给模型判断的事**写成了常量。
能写成“事实 + 判断标准”的，就别写成“结论”。

**但要注意**：人格（她是什么样的人）和处境（此刻她该有什么情绪）不是一回事，
**不能把人格也去结论化**——那等于把她的性格抹平。可借的是原则：**别替模型做它自己能做的判断**。

**代价**：改写人格里“结论式”的段落（比如【动手之前】那条其实自带了判断标准，属于可以留下的）。

---

### 2. 确定性优先（对方 §4.3）

**他们怎么做的**：首选概率 ≥0.55 且领先 ≥0.15 时**直接采纳**，只在竞争态才抽样。
实测日志：确定性直选 547 次、抽样 593 次——约一半决策走规则，一半走抽样。

**我们现在的样子**：`recall.ts` 的 `sampleIndex` **永远抽样**。哪怕证据压倒性，也还要摇一次骰子。

**为什么值得借**：
我们想要“每次想起的略有不同”，但那是**在候选差不多的时候**才合理。
证据 0.9 vs 0.1 还抽签，等于让“她明明很确定”的事变飘，还会让同一句话两次答得不一样（她已经因为这个被问过）。

**代价**：`recall.ts` 加 3 行（`if (top - second > 0.15 && top > 0.55) 直接取`）。

---

### 3. 反刍抑制（对方 §2.6）

**他们怎么做的**：只压**负面情绪**记忆（命中 ≥6 次才降权）；**事实类与关系类豁免**。

**我们现在的样子**：没有。负面记忆反而占便宜——`arousal` 加成 + 命中强化，越难受的事越容易被翻出来。

**为什么值得借**：
“反复翻同一次难过”是这类系统最像 bug 的行为。
他们的设计很克制：**只压负面、只压反复出现的、事实和关系类不动**——这三条限定正好避开了“把重要的事也压掉”。

**代价**：打分里加一条（需要记命中次数，`mentions` 已有）。
**风险**：阈值定错会把真实伤痛抹平（“那天到底多难受”就查不到了）。建议只降权、不删除。

---

### 4. 证据链（对方 §2.11）

**他们怎么做的**：写入时同时记证据（时间、来源、说话人），用于回溯“她为什么记得这条”，也便于回滚。

**我们现在的样子**：`source_turn_id` 只有 **1,049 / 2,399** 有值（44%）。LLM 抽出来的事件大多没有来源。

**为什么值得借**：
现在问她“你为什么记得这个”，她只能再检索一遍给你看；有了证据链，可以直指原话。
而且我们的 `cold://` 已经解决了“原文在哪”，缺的是“这条记忆对应哪句原话”。

**代价**：抽取时把 `turn_id` 写进去（v3 抽取已有 `evidence` 字段，没落库）；历史数据可回填。

---

## 二、值得借：要动结构（P1）

### 5. 惊讶度编码（对方 §2.2）

**他们怎么做的**：`s = 1 - max Jaccard(text, m_i)`；初始权重 `w0 = w_base × (1 + s)`（主人 4.0，其他 1.5）。
**全新的信息权重高，又一次重申的权重低。**

**我们现在的样子**：只有 `strength`（重复加强 ×1.25）——**没有“意外性”这一维**。
第一次听说和第十次重申，初始权重一样。

**为什么值得借**：
人对“意外”记得格外深；对“又提一遍”几乎不加工。
我们现在是反的：**提得越多越重**，等于鼓励她记住重复的东西，而不是新东西。

**代价**：抽取时算一次 Jaccard（我们已经有 bigram，可直接复用）。
**风险**：低。只影响初始强度，不影响后续召回逻辑。

---

### 6. 分区检索（对方 §2.7 / §2.10）

**他们怎么做的**：问题先分到若干 region，**只在对应分区内打分**；分区内不够再回退全库。
后来还加了“分舱”：按向量聚成 8 舱，先比质心取 top 2 舱。实测候选集从 143 条降到 39–73 条，路由开销 0.1ms。

**我们现在的样子**：**全库线性扫描**——2,399 条每条都算 bigram + IDF。库再长一倍，这步就会明显变慢、变糊。

**为什么值得借**：
这是**库长大后的必需品**，不是优化。
而且我们有天然的分区：**锚点的 kind**（人 / 地 / 场景 / 事 / 话题）。一句“我妈手术”，person + event 两个分区就够了。

**代价**：`recall.ts` 加一层粗筛（先用锚点命中定分区，再在全库/分区内打分）。
**不借“分舱”**：那需要向量，我们零依赖。可以用“锚点聚类”近似。

---

### 7. 边类型化（对方 §2.12）

**他们怎么做的**：四种边，各带系数——`co`（共激活）1.00 / `temporal`（同一时段）1.00 / `tag`（共享标签/主题）**1.25** / `ground`（同一地点）1.15。

**我们现在的样子**：只有 `same-day`（15,916 条）和 `co-occur`（136 条）两种，强弱全靠衰减。

**为什么值得借**：
“同一天提过”和“同一个主题”不该一样重。我们 15,916 条边里绝大多数是“那天凑巧都出现了”，
**噪音其实很大**——`tag` 类边（真正同主题）会更准。

**代价**：建边时分类（`anchors.ts` 已有 `relation` 字段，加枚举值即可）。

---

### 8. 上下文滚动交接（对方 §7.1）

**他们怎么做的**：满 25 轮把最近消息压成 **3 句交接（约 95 token）**，新会话带着它；旧映射清掉。

**我们现在的样子**：库里留 50 条、送 30 条，**超了就硬截断**——第 31 条之前的事她完全不记得，也没有摘要。

**为什么值得借**：
长会话里“上午说的事”会整段消失。一句交接就能救回来，而且比多塞 10 条历史省得多。

**代价**：要做一次摘要调用（或复用睡眠抽取的中间产物）。
**风险**：摘要会失真；建议只在“历史被截断”时才生成，且允许她取原文（`memory_recent` 已能翻）。

## 三、不建议借

| 对方的东西 | 为什么不借 |
|---|---|
| **向量嵌入 / 512 维双通道** | 破零依赖（要本地模型或 API）；而且**人格约束不能靠相似度命中**——“不许编造过去”不该等它语义相近才被想起来 |
| **分舱（8 舱质心）** | 同上，需要向量。可用“锚点聚类”近似替代 |
| **六维驱力 + 类量子抽样（复振幅/玻恩规则）** | 我们的走神用“随机锚点 + 四问”已经解决了主动性；再加一层驱力积分和相位抽样，**复杂度翻倍而收益不明确**。而且他们自己也在 §4.4 承认：状态结论化不好，才改成只喂事实 |
| **具身模拟（房间图 / 岛面坐标 / 天气 / 生态经济）** | 需要一个“她住在哪”的世界模型。凝没有住处——她住在 QQ 里。做这个等于另做一个游戏 |
| **49 条定时任务 / 看护重启** | 我们是单进程 + 一个 SQLite，重连由 OneBot 层处理。抄这套只会增加不可预测性 |
| **卦象 6 位编码** | 概念漂亮，本质是“离散特征做多样性桶”。我们**可以用更简单的**：层（3）× 情绪极性（2）× 锚点 kind（5）就已经够分桶 |

## 四、反过来看：我们有、他们没有的

| 我们的东西 | 他们对应 | 差别 |
|---|---|---|
| **三层预算下沉 + 冷存储地址** | 热库/冷库按节点数与权重下沉 | 我们有“原文永久留、上下文只给 `cold://` 地址”这一层，他们没有 |
| **情绪双轨（当时 / 现在想起来）** | `valenceBias` 只参与打分 | 我们把“当时的感受”和“现在想起来的感受”分开存，避免用后来的平静冒充当时的难受 |
| **能改自己（7 个文件 + 12 个工具）** | 行为参数自我调整（`reply_max_chars` 等） | 我们能改人格、说话规矩、抽取规则、走神提问——不只是参数 |
| **走神的四问结构** | 六维驱力 + 抽样决定动作 | 他们决定“动作”，我们决定“想起谁 + 要干什么” |

## 五、他们那份文档本身，最值得学的是体例

这四条比任何技术点都值钱：

1. **效度声明**（§11）：明写“无主观体验”“量子是数学借用”“卦象是 6 位编码，不涉及占断”。
   我们已经有类似的（`docs/spec.md` §9），但可以说得更硬。
2. **系数稳定性分类**（§12）：把参数分成「结构常量 / 自动调参 / 随记忆漂移 / 行为参数」，各自说明稳定性。
   我们的 `tuning.json` 现在混在一起——**这个分类法可以直接抄**。
3. **每节写「取舍说明」**：例如“完全放开会使成本上升 3~5 倍，所以检索仍由状态参与筛选”。
   这比只写“我们怎么做的”有用得多。
4. **术语中英对照表**：对外沟通成本立刻降一半。

---

## 六、如果只做三件

| 顺序 | 做什么 | 为什么先它 |
|---|---|---|
| 1 | **确定性优先**（P0-2） | 3 行代码，直接解决“同一问题答得飘” |
| 2 | **证据链**（P0-4） | 让“为什么记得这条”可回答，也是后面所有调试的地基 |
| 3 | **分区检索**（P1-6） | 库还在长，这是唯一会随规模恶化的那项 |

反刍抑制排第四：它改的是行为观感，容易看出效果，但阈值需要观察几天再定。
