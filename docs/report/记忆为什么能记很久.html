01一句话：它不是「存不下」，是「有意识地变模糊」

每多记一层，一条记忆就掉一层皮，体积随之掉一截。所以同样一块地方，越旧的内容越省，装下的时间就越长。

第一层 113 token→ 丢正文 →第二层 55 token→ 丢前因后果 →第三层 40 token

记忆条数不变，但每条占的地方变成原来的一半、再变成三分之一。这就是它能撑三年多的算术原因。

03为什么「越往下越便宜」是这套系统能长久的关键

不是玄学，是三处硬编码的取舍：

① 正文最贵，最先丢

一条记忆 113 token 里，有 58 是正文。丢掉正文 → 55 token，直接省一半。而「有这件事」这个信息还在。

② 前因后果也贵，第二个丢

再丢掉前因 + 后果 → 40 token，又省 27%。剩下的「感受 + 一个画面」正好是人回忆很久以前的方式。

所以同一个 1,000,000 token 的池子：

  • 如果全都按第一层存，只能装约 8,800 条（714 条/天 → 12 天）
  • 三层摊开之后，能装 约 101 万条（→ 3.9 年）
差 114 倍。这不是压缩算法的功劳，是「允许自己忘得越来越粗」换来的。

04不会爆的原因：预算只在「活跃的部分」上花

她说话时往提示词里塞的只有第一层 + 一小撮第二层。第三层（archived=1）根本不进上下文，所以不吃 token 预算，只吃磁盘。

换句话说：池子的大小决定「能想多细」，进料速度决定「多久填满一层」，两者分开管，才不会被日常对话挤爆。

05关系网（边）也不会无限涨

记忆之外还有一张锚点关系网。它最容易被灌爆——「同一天出现过」的边是 n×(n-1)/2 条，一天 100 个锚点就是 5,000 条。

现在按「这条边挂着的记忆在哪一层」分三档处理：

边半衰期底线上限现在
热边（还挂着第一层记忆）15 天0.05不设上限1,785 条
温边（只剩第二层）3 天0.10超 20,000 → 砍到 50%9,269 条
冷边（只剩第三层）2 天0.20超 2,000 → 砍到 50%1,102 条

外加两条：热转温那一刻，新变温的边只留 25%；co-occur（真共现）不参与削减。实测把 27,807 条温边删掉，7 个测试查询的召回条数一条没变。

06原文永远不会丢：底片机制

每次把一条记忆往下压之前，先把它的全文写进 cold_archive，留一个地址：cold://ev_xxxxxxxx。

  • 平时不读 → 不占 token
  • 真需要时按地址取回 → 原文一字不少
  • 关键词撞上了还会被"唤醒"（coldHints）

所以「记不清细节」和「找不回来」是两件事。现在底片里有 1,600 条原文、共 16.7 万字。

07磁盘账：一年约 226 MB

实际还更省：冷存储原文平均只有 104 字/条（0.3 KB）。真正占地方的是化石行本身（标题+片段+索引），约 0.6 KB/条。

09代价：它是有意变模糊的

  • 3.7 天以后，她还能说清「有这件事」，但不能再复述原话
  • 16 天以后，只剩「那次挺难受的，好像跟钱有关」这种程度
  • 要细节，得靠底片地址去翻，或被关键词唤醒

这不是 bug，是设计：用逐渐变粗的记忆，换一个几乎不会爆的上限。想让她「记得更细更久」，只有两条路——降进料速度（记忆更值钱）或加大预算（更贵）。
