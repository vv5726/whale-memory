# 未来升级：信息量不该由规则算

> 现在这套「留哪条」的判断，是正则和长度堆出来的。它能用，但它不是答案。

## 现状

`tools/distill.ts` 里判断一条记忆值不值得留，用的是：

```
关键事实数 × 2
+ 正文字数 ÷ 10
+ 有说话人 +1
+ 分过类   +1
+ 含数字   +1.5
+ 标题短   +0.5
```

排序后每组留前 3 条。

**问题**：

1. **它衡量的是「像不像一条好记忆」，不是「值不值得留」**
   一条 40 字、带数字、分类正确的废话，得分会高于一条 15 字但关键的「他说不行」。

2. **它不懂语义冲突**
   「他说要来」和「他说不来了」——字面得分一样，规则分不出哪条该失效。

3. **它不懂「这件事对谁重要」**
   同一句话，主人说的和群友路人说的，权重完全不同。现在只加 1 分。

4. **权重是拍脑袋的**
   为什么实事数是 2 分不是 3 分？为什么数字 1.5？没人验证过。

## 该换成什么

**用一个模型调用给每条记忆打「留」的分数**，输入是：

```
- 这条记忆本身（标题 + 正文 + 关键事实 + 说话人 + 分类）
- 同一组里的其它记忆（才知道什么叫「重复」）
- 时间（越新越优先，但不绝对）
- 谁说的（主人 > 群友；问过的事 > 没问过的）
```

输出三个可解释的字段，不是单一分数：

```json
{
  "verdict": "keep" | "demote" | "superseded" | "noise",
  "reason": "一句话说清为什么",
  "superseded_by": "哪条替代了它（如果能指出）"
}
```

**为什么必须是模型而不是规则**：

- 「重复」是语义判断——换个说法说同一件事，字面毫不重合
- 「被推翻」需要理解因果——「后来改主意了」不等于「之前那条错了」
- 「值不值得留」本质是「将来会不会用到」，这是预测，规则做不了

## 成本

一条记忆一次调用，约 200 token 进、50 出。1000 条记忆 = 约 0.15 元。

**比规则贵，但比留一堆垃圾便宜**——垃圾的代价是每次检索都被稀释，而那个代价看不见。

## 落地方式（不急）

```
1. 保留现有规则分，作为「快速档」
2. 加一个开关 memorySettleMode: "rule" | "model"
3. model 模式下，睡眠结束时对「同一组里超过 3 条」的那些组调模型裁决
4. 裁决结果写进 events.verdict / verdict_reason，检索时按 verdict 加权
```

**先别做。** 等规则档在真实数据上跑够两周，看它到底在哪儿判错——那时候才知道该把哪几类交给模型。

## 一个更远的方向：让分数可校准

现在是「我觉得重要」，将来应该是「**被用过几次才重要**」：

```
一条记忆被检索出来 → 回答里真的用到了 → 算一次命中
命中次数多的，信息量自动升高
检索出来但从没被用过的，慢慢降权
```

这是**用结果反过来校准取舍**，比任何静态规则都准。

需要的前提：记录「检索 → 是否被采用」的链路。现在没有。
