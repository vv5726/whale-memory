# 设计细节与取舍

这份文档讲**为什么这么做**，以及我们踩过的坑。想改之前先读一遍，能省几天。

---

## 一、为什么是「预算驱动」而不是「时间驱动」

直觉做法：30 天前的事就压掉。

问题：**同样 30 天，事情的重要性差一百倍。** 三十天前的「今天中午吃了什么」和三十天前的「确诊结果」，按时间一刀切会一起被压。

所以改成按预算：

```
总占用 > contextBudgetTokens  →  从 (重要度最低, 最旧) 开始往下沉一层
```

重要度取 `strength`（重复加强后的值）和层级本身。这样：

- 预算很紧时，只有最核心的几条留在 detailed
- 预算很宽时，什么都不会沉
- 加记忆不会让已有记忆突然变模糊，除非真的超了

**副作用**：`contextBudgetTokens` 设很大（比如 20 万）等于关掉压缩。要看压缩效果得设小（3000–8000）。

## 二、四层，单向

```
detailed → compressed → fossil → 冷存储
```

**为什么不许往回升？** 因为正文已经没了。compressed 那条只存了起因、结果、核心片段——回不到 detailed，除非重新问一遍。

这不是缺陷。人也是这样：你记得「那年去云南玩得挺好」，但想不起每一天的细节；除非有人再讲一遍，你才重新有细节。

## 三、key_facts：唯一穿透所有层的东西

金额、日期、结论、号码。

为什么单独存？因为**正文可以被压缩，但这些不能错**。

- 「病理结果是良性」→ 正文压成「等了七天」之后，`["良性"]` 还在
- 「王建国欠两千块」→ 正文压成「他后来还了」之后，`["两千块"]` 还在

这条是整套里**最该抄的**。绝大多数记忆系统在压缩时会把关键事实一起压掉，然后就再也答不准了。

## 四、锚点：为什么不是向量检索

向量检索的问题不是不准，是**没有结构**。

你问「我妈那次手术」，向量库会找「字面像」的段落。但如果当时的对话里说的是「她推进去的时候我一直站在门外」，向量匹配不到「手术」两个字。

锚点走的是另一条路：

```
「我妈」→ 锚点「妈妈」→ 关系 → 「甲状腺手术」→ 挂着那件事
```

**扩散激活**：命中的锚点算满，沿边走一层算一半，两层算四分之一。所以一次命中能把整片区域带出来。

「同义合并」：如果「老王」和「王建国」被反复认成同一个（关联强度到 100%），睡眠时真的并成一个节点。之后不管用哪个名字都能找到。

## 五、情绪：两个层次

**每条事的情绪**（valence/arousal）：存下来，检索时用来排序（情绪强的更容易被想起来）。

**整体心境**：由近期记忆加权算出，存在 `mood_state`。**读取时按半衰期 10 小时回落。**

为什么回落？不回落的话，两个月前那场气会一直挂在脸上。那不是记性好，那是 bug。

## 六、两条检索通道

- **事实通道**：确定性的，按证据排序，取 top-k。同一个问题永远同一个答案。
- **情绪通道**：softmax 采样，种子 = 会话 + 当天。所以同一天问同一个问题，答案是稳定的；换一天，可能想起别的。

为什么要采样？因为人不是每次都想起来同一件事。全确定会显得机械。

**相关性闸门**：用「证据」而不是「最终分」来判定「有没有想起来」。因为久远的记忆可达性低，会在最终分里排不上去，但只要线索确实指向它，就不能当成「没想起来」。

## 七、写的时候就要带上下文

存一条新记忆时，先看前后 7 天：

- 有没有共同锚点
- 最近提过谁

这样「她又说了那个事」在新记忆里能落到具体的人身上，而不是存成一个孤立的「她」。

## 八、冷存储与挖回

压到化石还嫌多时，事会进 `cold_archive`：

```
address   cold://ev_xxx
gist      一句话摘要（这是唯一还留在主库的线索）
```

检索时如果发现「主库里没想起来，但冷存储里有东西可能相关」，会返回一个**地址提示**（不是正文，省 token）。

明确说「挖一下 cold://ev_xxx」才会去取。这是**懒加载的记忆**。

# 踩过的坑（这些比设计更值钱）

## 1. 抽取缓存按「天」缓存，把后来的话全跳过了

第一版：`llm_extractions` 表按 `day` 做键，冻结抽取结果保证幂等。

结果：**今天第一次抽完之后，后面所有新说的话都被当成「这天抽过了」跳过。** 329 条对话被标记为已处理，记忆一条没涨。

修法：缓存键改成「这一批对话的指纹」（条数 + 总字数 + 首尾内容）。

**教训**：幂等缓存一定要按**输入内容**做键，不能按「时间窗口」做键。

## 2. B站字幕接口：不带签名会返回**别人的**字幕

请求 `player/v2?aid=..&cid=..` 不带 wbi 签名时，返回的 `subtitle_url` 每次都不一样，内容是别的视频的字幕。

**这种错误极难发现**：格式对、内容通顺、就是不对。如果直接信了，会一本正经地聊一个不存在的视频。

修法：加 wbi 签名（MD5 + 置换表算 `w_rid`）。

**教训**：外部数据源如果「时好时坏」，先怀疑签名/鉴权，别怀疑解析。

## 3. 判定条件写太宽，把该答的也拦了

「防幻觉守卫」最初的条件是：检索没命中 + 回答里有数字 → 判为编造。

结果误伤了三次：

- 「我希望你说话短一点」→ 当成提问 → 答「我不记得」
- 「你看懂这句话了吗」→ 当成问往事 → 答「没看懂」
- 「1万次」和「一万次」→ 字面不等 → 判为编造

**教训**：拦截规则宁可窄，不要宽。误伤（明明知道却说不知道）比漏拦（可能编）伤害大——漏拦还有别的网兜着。

## 4. 把「不主动发消息」写进提示词，它就真的不说话了

一度在「自主活动」和「玩手机」两处都写了「不要主动给对方发消息，你是在过你自己的时间」。

结果：它一天都不主动找人说一句话。

**教训**：提示词里的每一条「不要」，模型都会严格执行。写之前想清楚是不是真的要。

## 5. 角色扮演会传染成口头禅

兜底句子固定写成「这个我真没印象，你说的是哪次？」

结果它把这句话变成了自己的口头禅，对什么都说，连下指令都回这一句——因为历史对话里见过自己这么说。

修法：兜底句改成几种轮换。

## 6. 一 Action 一半：工具轮次上限太低

每次行动最多 8 轮工具调用。玩手机时它开个 App、读一屏、就自动收尾了——因为轮次用完了。

修法：不同场景不同上限（普通 8 / 玩手机 25 / 想事情 20），并且提示词里说「别做一件事就停」。

## 7. WAL 模式复制数据库会丢数据

合并多个记忆库时，直接 `copy` 那个 `.db` 文件——只拿到一部分。因为最近的写入还在 `-wal` 文件里。

修法：先 `PRAGMA wal_checkpoint(TRUNCATE)`，再复制。

# 如果只能抄三条

1. **key_facts 穿透所有层**——压缩正文，不压缩事实
2. **预算驱动下沉，不是时间驱动**——重要性差一百倍，时间不能一刀切
3. **外部数据源先验签名**——不带签名的接口可能给你别人的数据
