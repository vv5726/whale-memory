# 项目状态与反思（2026-10-28）

> **一句话**：这是一个跑通的实验项目。**思路可用，代码不再继续迭代。**
> 作者已经看到这套做法的局限，准备换新架构；这里留的是**踩过的坑和验证过的结论**，
> 不是一份可以直接拿去运行的成品。

---

## 一、最硬的实测：对话里，工具定义占掉了三分之二的 token

2026-10-28 的实测（489 次调用 / 18.24M 输入 / 缓存命中 51%）：

| 用途 | 次数/天 | 每次 token | 合计 | 占比 |
|---|---|---|---|---|
| **对话**（含工具环） | ~213 | **~50k** | 10.8M | **59%** |
| 走神 | 242 | 7.4k | 1.8M | 36%→ 已瘦身 |
| 批处理 | 1 | ~280k | 0.3M | 2% |
| 阅读 + 学习 | 1 | ~170k | 0.2M | 1% |
| 抽取/睡眠 | ~16 | ~20k | 0.3M | 2% |

**对话第一轮 24k 的构成**：

```
人格 + 底线 + 【我】 + 额度 + 今天 + 计划   ~2,200
记忆 + 谁是谁 + 场景 + 读心 + 统计          ~2,000
说话规矩                                   2,500
66 个工具定义                             16,000   ← 占 2/3
30 条历史                                  1,500
──────────────────────────────────────────────
                                           24,000
```

**这就是这套架构的致命成本**：工具 schema 是**固定成本**，每轮都发一遍；
而工具结果**从不折叠**，一条回复 3.8 轮，第 4 轮要背前三轮的全部结果。

对照：走神把工具从 63 个砍到 3 个之后，每次从 ~27k 降到 **6.8–7.4k**（实测，
见 `data/logs/llm-usage.log`）。同一件事在对话里做不了——因为对话真的需要工具。

## 二、作者自述的局限

1. **工具定义是纯固定成本，随工具数线性增长**
   74 个工具 = 26,870 字符 ≈ 16k token。想省只能砍工具，但聊天随时可能用到任何一个。
2. **工具结果没有折叠机制**
   折叠过一次算过账：取回率超过 10% 就白干。没敢上，所以这条一直没解决。
3. **提示词越写越长，越长越稀释**
   说话规矩一天之内从 1,094 字涨到 3,812 字——因为她每次“改自己”都在加。
   加到最后，靠前的规矩会被靠后的挤掉。这个问题提示词层面解决不了。
4. **缓存排序是小事但没人做**
   说话规矩排在系统提示最末尾，而前面任何一段变（比如【今天】）都会让它从命中变未命中。
   走神实测：总共 7.4k，命中只有 1.7k。
5. **并发靠约定，没有真正的调度器**
   走神、批处理、对话三边共用一个 SQLite，靠 `busyRecently()` 和几个 flag 互相避让。
   今天真出过事：为了检查语法 `import('./src/bot.ts')`，起出了**第二个 bot 实例**，
   两边抢同一个 OneBot 连接、同一份队列文件。
6. **“能改自己”是把双刃剑**
   她一天改 53 处规矩。改得越多，越难解释她为什么这么说；而且她改的东西
   有时写错了地方（写进知识库而不是说话规矩），不会报错，只是不生效。

## 三、新架构的方向（只记想法，不承诺）

这套做法卡住的地方，是**把所有东西塞进一个上下文窗口里**：
人格、记忆、工具、历史、工具结果，全在同一个 prompt 里互相挤。

如果要重来，会往这几条走：

- **工具不进主上下文**：把工具调用交给一个独立的、只带 schema 的执行层，
  主对话只看到“我调用了 X，结果是一句话”。
- **记忆按需加载**，不是一个固定大小的块。
- **规则用机制而不是提示词**：能写成代码检查的，就别写进人格。
- **单一调度器**：所有后台动作（走神/批处理/整理）排一个队，而不是三个定时器互相避让。

## 五、给读者的建议

**抄思路，别抄实现。**

值得参考的四个结构（都在 `docs/` 里写了）：

1. **预算驱动的分层记忆**（`spec.md` §2.4）——detailed / compressed / fossil，
   只往旧的方向沉，永不回弹。比“按时间删”稳定得多。
2. **锚点图 + 激活扩散**（`spec.md` §2.5）——记忆不是平铺的，是挂在人/地/事上的；
   想起一件事会顺着关系带出别的。
3. **走神的四问结构**（`think-prompt.md`）——目的 / 途径 / 消息 / 给谁。
   逼它先想清楚“我要什么”，再决定“用什么方式”。
4. **队列 + 批处理**（`batch.ts`）——把「想」和「做」分开：
   想的时候只记账（3 个工具，7k token），做的时候攒够一次性办（8 件一批）。
   今天走神从 27k 降到 7.4k，主要就是这个。

**不建议照搬的**：74 个工具全塞进上下文的做法、纯提示词的自我约束、
以及靠 flag 互斥的多定时器。
