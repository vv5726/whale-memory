# 凝 · 现状施工图

> 给「想照着做一套」的人。
> `docs/architecture.md` 讲的是**为什么这么设计**（取舍与踩坑）；这一份讲**它现在长什么样、怎么照着搭**。
> 数字取自 2026-10-26 16:45 的线上库，代码取自当前 `src/`（13,187 行，零依赖 Node 24）。

---

## 一、它是什么

一个跑在 QQ 上的机器人（OneBot 11 / NapCat 接入）。和「收到消息就调模型」的机器人最大的区别：

1. **记忆是结构化的**：原始对话会先变成「事」，事挂在「锚点」上，锚点之间有边；
   检索是「想起谁 → 带出什么」，不是「找字面相似的段落」。
2. **有遗忘**：四层（detailed → compressed → fossil → 冷存）+ 预算驱动下沉 + 边衰减。
3. **有自己的时间**：走神（1.5–3.5 分钟一次）、自主活动（6 分钟一次）、睡眠整理（聊完 3 分钟）。
   回话只是其中一条路，不是全部。
4. **身份是自己写的**：`data/self.md` 由它自己维护，代码只留底线。

**两个 service 实例**是刻意的：聊天要按人/群隔离，自主活动要「一个人住」，但库是同一个
（她和主人是同一段人生）。代价：**状态不能挂在实例上**（见第 6 节第 4 条）。

## 三、记忆结构

### 3.1 三层 + 一条冷地址

| 层 | 表 | 存什么 | 怎么用 |
|---|---|---|---|
| 原始层 | `turns` | 一句一句对话，`processed=0` 待整理 | 拼提示词直接取最近 50 轮 |
| 事件层 | `events` | 整理成「事」，带情绪/层级/状态 | 打分 + 激活扩散 |
| 冷存层 | `cold_archive` | 压掉的细节，按地址存 | 先给地址提示，要细节再 `deref` |

### 3.2 一条事件

```
events: id, title, detail, kind(event/user/feedback/project), ts, tier,
        etype, status, memory_value, sensitivity, evidence(json),
        affect(valence/arousal), key_facts, pinned, archived, stage
```

v3 抽取新增的四个字段，都是为了让「答得准」：

- `etype`：信息 93 / 经历 68 / 待办 49 / 决策 41 / 冲突 13 / 约定 4
- `status`：已发生 99 / 需跟进 62 / 仅记录 47 / 已定 41 / 待确认 19
- `evidence: [{speaker, msg_id, quote}]`：`msg_id` 必须抄对话里的编号，**编的会被校验丢掉**
- `memory_value` 0–10（未来会被问 / 涉及人情绪 / 有时效 / 证据明确 / 重复变化 各 2 分）

`key_facts`（金额、日期、结论、号码）**穿透所有层**：正文可以压掉，这些不许丢。

### 3.3 锚点网络（骨架）

```
anchors 356   事 267 · 人 11 · 环境 3 · 旧版 64（停用）· 合并残壳 10
anchor_aliases  97   同一个人的多个叫法 → 同一个节点
event_anchors 4,901  事 ↔ 锚点
edges        18,848  锚点 ↔ 锚点：一对一行、每锚点上限 20、随时间衰减
```

检索路径：**匹配锚点（含别名）→ 沿边扩散一跳（命中满、一跳一半、两跳四分之一）
→ 候选记忆打分 → 情感抽样 → 冷地址提示**。

**人这一块是单独的图**（`src/person-graph.ts`）：

```
people（QQ 号）── external_id / 别名 ──► 锚点（名字锚点与号码锚点是同一个人）
event_anchors.role：speaker（谁说的）/ subject / mentioned（只是被提到）
提示词里按人挂内容：10000002 = 某某
                     他说过的：「…」「…」
                     关于他的：「…」
```

`role` 是从 `events.speaker_id`（睡眠里由 `turns.speaker_id` 带过来）写的，幂等；
这样「知道提过谁」升级成「知道谁说的、什么事是关于他的」。

**群名册**（`group_members` 表 + `group_members` 工具）：从 OneBot 的 `get_group_member_list`
整群同步（启动后一次、之后每 30 分钟），所以没开过口的人它也知道。提示词里只放一行：
`这个群共 5 人：…；其中 3 个开过口，其余 2 个你只见过名字`，人多时只给前 40 个 + 提示调工具。
名册**不塞进 people** —— people 是「跟她说过话的人」，混在一起会把【谁是谁】挤满。

「谁说的」这个字段有三种写法，都要认：号码（`10000001`）、名字（`对方` / `某某`）、
自称（`凝` = 她自己，她也在 people 里）。**代词（他/她/你/我）不进库**——抽取提示词
里给没标说话人的消息打的是「（没标说话人）」，不是「他」，否则模型会照抄成说话人；
历史遗留的代词靠 `evidence.msg_id → turns.speaker_id` 倒回真人（那是证据链，不是猜）。

### 3.4 打分与闸门

```
证据 = 锚点证据 + 字面 bigram + FTS 全文（< 0.05 直接排除）
分数 = (证据 + 情绪唤醒 0.35 + 近期性 0.1) × 说话人系数 × 质量 × 标题命中
       + 钉住 0.6 × 证据 × 层级可达性(1.0 / 0.75 / 0.35)
wakeThreshold 0.45：低于它就是「这次真没想起来」→ 提示词里禁止给具体数字
```

两条容易被忽略但很关键的：

- **情感抽样**：强命中之外按唤醒度 softmax 采样，模拟「突然想起」，不是噪声。
- **冷提示**：只给 `cold://ev_xxx` + 一句摘要 + 命中关键词，要细节再取（懒加载记忆）。

### 3.5 睡眠 = 可重跑批处理

```
① extract   turns → events（带 etype/status/evidence/memory_value）
② contract  100% 关联的锚点合并
③ consolidate  detailed → compressed → fossil
④ decay     锚点 / 边权重衰减
⑤ pins      到期失效、待跟进延后
⑥ mood      当天情绪基线
⑦ stats     落 sleep_runs
```

聊天时**绝不整理记忆**；每一步幂等，中途崩溃/被叫醒都能原地重跑（已跑 134 次）。

### 3.6 现状数字

```
事件 1,505（活着 1,216：event 1,093 / user 84 / feedback 34 / project 5）
层级 详细 457 / 压缩 759
锚点 356 · 别名 97 · 事-锚点 4,901 · 边 18,848
原始对话 1,635 轮（未整理 8）· 冷存 946 · 待跟进 62
知识库 129 条（梗 63 / 记忆系统 47）· 人 6 个
```

## 四、行为结构

### 4.1 一次回话：8 步

```
1 收消息    CQ 码翻人话（表情查 id 表；图片交「眼睛」看）
2 落库      ingestTurns（原始对话先存，睡眠时再整理）
3 读心      readMind → 潜台词 / 情绪 / 我听完的反应（只当背景，别复述）
4 取历史    最近 50 轮（★ 必须在落库之前取，否则当前这句算两遍）
5 检索      recall：锚点 → 扩散 → 打分 → 情感抽样 → 冷提示
6 拼提示词  人格底线 + self.md + 额度 + 今天 + 记忆 + 读心 + 场景 + 谁是谁
7 工具环    最多 24 轮；工具返回值算合法事实来源
8 校验落库  编造检查 → 存回复 → 更历史 → 睡眠计时
```

### 4.2 四条时间线

| 循环 | 节奏 | 干什么 | 闸门 |
|---|---|---|---|
| 回话 | 消息驱动 | 上面 8 步 | 白名单 / 群模式 / 防刷 |
| **走神** | 随机 1.5–3.5 分 | 随机锚点 → 六问 → 三途径 | 见 4.3 |
| 自主活动 | 6 分钟 | 骰子 → 阅读员看 B 站 → 只写手记 | 时段 / 额度 / 有人说话 |
| 睡眠 | 聊完 3 分钟 + 每天 3–5 点 | 那 7 步批处理 | 幂等、可中断 |
| 主动说话 | —— | 已停用，只从走神出 | —— |

### 4.3 走神：唯一的主动说话路径

```
thinkEnabled?            关着就走
刚忙完（90 秒内）?        缓一下        ← 看全局活动时间，不看本实例
他 30 秒内说过话?         不走神        ← thinkIdleSeconds 真的在判
在活动时段？掷骰子（0.85）?
最近 12 小时想过的锚点    排除（防原地打转）
六问：想知道什么 / 下一步 / 想做什么 / 怎么完善自己 / 要不要整理记忆 / 聊天哪里没做好
三途径：做（self_note、kb_add）· 内容（B 站）· 聊天（直接发）
→ 只有「聊天」会真的发出去，且规则写着：
   「想到的正是刚在聊的、或刚被否掉的就别发；别催他」
```

**走神内容里没有抖音了**：提示词只留 B 站，手机工具层还硬拦
（`phone_open_app` 包名 `aweme`、`phone_tap_text` 文字含「抖音」都直接回「不看抖音」）。

### 4.4 工具（38 个，六组）

| 组 | 数 | 代表 |
|---|---|---|
| 基础 | 1 | get_time |
| 手机（ADB） | 11 | 截图 / 点 / 滑 / 打字 / 开 App / 读屏文字 |
| B 站 | 8 | 热门 / 排行 / 搜索 / 字幕 / 点赞 / 评论 / 弹幕 / 动态 |
| 自我 | 5 | self_read / self_write / self_note / self_journal / read_log |
| 记忆 | 9 | memory_recent / recall / save / tidy / why / pin / about / list / **group_members** |
| 策略 | 4 | 说话规矩 / 抽取规则 / 群策略 / 参数调优 |

三条铁律：每个工具自带 JSON Schema；返回**一行短文本**（截图不整张塞）；
出错**不抛到对话层**，返回一句人话。

### 4.5 「自我」不是代码写的

```
data/self.md         它自己写（我是谁 / 怎么说话 / 在乎什么 / 还在想什么），每次开口前注入
data/speech-rules.md 它自己定的说话规矩，追加在系统提示词最后（优先级最高）
data/tuning.json     温度、群聊门槛、工具轮数，它自己可调
data/journal/*.md    手记：走神、玩手机、想通什么都会写，它自己也能读
data/thoughts.json   最近想过什么（12 小时去重）
```

代码只留底线：不编造、不演客服、短、分清谁说的。**别的都能被它自己改掉。**

## 五、为什么它「像记得」

1. **想起谁，而不是匹配词**：锚点 + 一跳扩散 → 「我妈那次手术」能牵出整片区域。
2. **记不住是设计**：分层 + 衰减 + 冷地址，主动让它忘，只留地址。
3. **整理在睡眠，不在对话里**：对话只做检索和说话，整理是批处理、可重跑。
4. **先读心再说话**：情绪/潜台词单独算一步，当背景塞回去，它不用一边分析一边说。

## 六、照着搭的最短路径（也是给 DSH 的施工单）

> 核心不是模型，是**调度**：什么时候忆、什么时候忘、什么时候自己开口。

1. **先建库，不接聊天**：三张表（turns / events / anchors）+ 一个抽取提示词，
   拿几十段真实对话跑「turns → events → 锚点」。**这一步占 60% 的坑。**
2. **再接检索**：锚点匹配 + 一跳扩散 + 打分，把拼出来的结果打出来人眼看「像不像想起来」。
3. **最后接行为**：回话主链 → 睡眠整理 → 走神/自主活动。每个循环先做「能停」再放开。
4. **闸门比功能先写**：谁能说话、什么时候能说、说完怎么落库（自己说的话也算历史）。

给 DSH 的四段话（可直接照抄当任务）：

```
① 做一个零依赖 Node 24 项目：turns / events / anchors / edges 四张表，
   写一个抽取函数把按天分组的对话变成 events（带 etype/status/evidence/memory_value），
   再写一个 recall(query) 用锚点匹配 + 一跳扩散打分。不许装依赖，用 node:sqlite。
② 给 recall 加三层遗忘：detailed/compressed/fossil，按 contextBudget 预算下沉，
   并加冷存表 + 地址提示。写一个 sleep() 把这套做成幂等批处理。
③ 接一个聊天主链：收消息 → 落库 → 取历史（在落库之前！）→ recall → 拼提示词 → 工具环。
   自己说的话也要进历史。
④ 加走神：随机锚点 → 六问 → 三途径（做/内容/聊天）。闸门先行：
   有人刚说话不走神、刚忙完不走神、12 小时内想过的锚点排除。
```

## 七、十个坑（按代价排序，都是现场长的）

1. **单测通 ≠ 能跑**：`import` 只证明语法。要跑真实入口，并把**运行时拼出来的提示词打出来**看。
2. **静默失效最贵**：`replace` 找不到锚点会原样返回，脚本还打印「成功」——
   「读心没进提示词」就这么丢了，文件和备份 SHA256 一模一样。
3. **别用 PowerShell 拼中文写源码**：`Set-Content` 会把中文变 `?`，数组 + `-NoNewline`
   会把 46KB 压成 1 行。用按字面替换的编辑工具。
4. **状态别挂在实例上**：聊天和走神是两个 service 实例，`busyRecently()` 只看本实例 →
   它刚回完话 1.6 秒就自己开口。活动时间、历史缓存必须跨实例共享。
5. **当前这句会被算两遍**：先 `ingestTurns` 再 `historyFor`，冷启动回填把当前句带进历史 →
   它以为对方说了两遍（表情包最明显）。
6. **自己说的话要进历史**：走神说的话只写进库，聊天那边缓存命中就不读库 →
   它看不见自己刚说的那句，你顺着回它答非所问。
7. **配置项要真的被读**：`thinkIdleSeconds` 一度只打在启动日志里，代码从没拿它判过。
8. **表情/图片会重复**：同一条里同一张图跑两次「看图 + 读意思」→ 花两次钱、写两遍描述。
   按 id / 内容 hash 去重。
9. **别让旧话题当新念头**：走神挑随机锚点，但嘴会顺着旧账说。必须给它「刚才在聊什么」。
10. **破坏性操作先备份**：一致性快照用 `VACUUM INTO`，别裸拷 `.db`（还有几百 MB 级 WAL）。

## 八、一句话

**你希望它「记得住」，还是希望它「想得起来」？**
这套东西全部的设计都在第二个上——记得住靠数据库，想得起来靠结构。
