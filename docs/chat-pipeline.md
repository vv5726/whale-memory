# 对话这条路的钱花在哪（分析，未实施）

> 数据来源：2026-10-28 实测。`daily_cost` 489 次调用 / 18.24M 输入 / 缓存命中 51% / ≈¥5.85。
> 走神实测已由 `data/logs/llm-usage.log` 验证：**每次 6.8–7.4k token，缓存只命中 1.7k**。

---

## 一、一条消息进来，会发生几次模型调用

```
QQ 消息
  ↓ OneBot WS
router.handle()
  ├─ 群白名单检查（不在白名单：只记群号，不回复）
  ├─ ① readMind()            ← 模型调用 #1（独立 prompt，max_tokens 160，**不记账**）
  └─ service.handle()
      ├─ 记 turn（ingestTurns）
      ├─ recall()             ← 本地检索，不花钱（但会扫全库）
      ├─ buildChatPrompt()    ← 拼系统提示（人格/底线/我/额度/今天/计划/记忆/工具/谁是谁/场景/读心/统计/说话规矩 + 30 条历史）
      ├─ ② respond(replyRounds=12)  ← 模型调用 #2..#N（工具环，每轮全量重发）
      │    └─ 回复 <4 字 → 放宽召回再跑一整轮（③，又 24k 起）
      ├─ 编造守卫（looksFabricated）
      ├─ 气泡拆分（本地，不花钱）
      └─ 记账、推历史、触发 maybeSleep
```

**实测：一条回复平均 3.8 次模型调用**（61 条 assistant 轮次 / ~230 次调用）。

## 二、每次调用里装着什么

### 走神（实测，最干净的一档）

| 块 | ≈ token |
|---|---|
| 人格 + 底线 + 【我】 | 1,700（**这就是缓存命中的那 1.7k**） |
| 额度 / 今天 / 计划 / 统计 | ~300 |
| 【记忆】召回块 | ≤1,200 |
| 说话规矩 | **2,500** |
| 走神自己的锚点+知识库+刚才聊什么 | ~800 |
| 3 个工具定义 | ~300 |
| **合计** | **6,800–7,400** |

### 对话

| 块 | ≈ token |
|---|---|
| 人格 + 底线 + 【我】 + 额度 + 今天 + 计划 | ~2,200 |
| 【记忆】+ 谁是谁 + 场景 + 读心 + 统计 | ~2,000 |
| 说话规矩 | 2,500 |
| **66 个工具定义** | **~16,000** |
| 30 条历史 | ~1,500 |
| **第一轮合计** | **≈ 24,000** |

之后每一轮工具调用，**整段重发一遍**，再叠加上一轮的工具结果（记忆检索 2–3k、手机截图 4–5k、B 站字幕 2k…）。

> 所以 47k 不是“一句话很贵”，是**几轮累积后的平均**。

## 三、六个问题（按金额排）

### ① 工具结果没有任何折叠（最大）

一条回复里如果调了 3 次工具，第 4 轮的提示词 = 24k + 结果1 + 结果2 + 结果3。而结果从来不会变短。
**估计吃掉对话开销的 30–40%。**

### ② 66 个工具每轮都塞（16k / 轮）

手机 11 + B 站 9 + 改自己 12 + 记忆 18 + 计划 7 + 表情包 5 + 知识库 4 + 其它 8。
**聊天里真正常用的不到一半。** 手机和 B 站加起来 20 个（约 8k token），一条普通回话里几乎用不上。

### ③ replyRounds = 12（上限太高）

12 轮 = 12 次全量重发。实测平均 3.8 轮，但少数长回复能到 8–10 轮，那一条就是 300k+。

### ④ 说话规矩 2,500 字排在最后 → 永远吃不到缓存

缓存按前缀匹配。现在顺序是
`人格 → 底线 → 我 → 额度 → 今天 → 计划 → 记忆 → 工具 → 谁是谁 → 场景 → 读心 → 统计 → 说话规矩`
**“今天”一变，后面全部作废**——包括那 2,500 字的说话规矩。

实测印证：走神总 7.4k，命中只有 1.7k（正好是人格+底线+【我】）。

### ⑤ 读心是一次独立调用，而且不记账

`read-mind.ts` 自己 `fetch`，没走 `recordUsage`。钱不多（max_tokens 160），但**账上看不见它**。

### ⑥ 30 条历史硬截断

第 31 条之前的事整段消失，没有摘要。而且这 1.5k 每轮都重发。

## 四、六个方案（照批处理那套思路）

| # | 方案 | 省多少 | 代价 | 风险 |
|---|---|---|---|---|
| **A** | **工具分档**：默认只给 ~24 个（记忆/计划/表情包/知识库/其它），手机·B站·改自己改成「要了才给」（她先说一句“我要用手机”，下一条起挂上） | **每轮 −8k**（≈ −17%） | 要加一个 `tool_load` 工具 + 一个 session 状态 | 她可能不知道该要——可以用提示词写清“你现在没有手机工具，要用就说” |
| **B** | **replyRounds 12 → 5** | 长尾砍掉，平均轮数 3.8 → 3.2 左右 | 一行改 tuning | 复杂任务（查三处资料）可能没做完就收尾 |
| **C** | **说话规矩上移**到【我】后面（稳定段） | 2.5k 从全价变 1/10 价，**≈ −2.3k 等效** | 改一行拼接顺序 | 无（顺序变了不影响语义） |
| **D** | **工具结果折叠**：旧结果换成 `⟨tool#3 bili_subtitle 1,234 字⟩`，要细节再取 | 每轮 −6~8k | 要写折叠 + 取回 | **取回率 >10% 就白干**（之前算过） |
| **E** | **历史改滚动摘要**：50 条压成 3 句交接 | −1k/轮 | 要加摘要调用 | 摘要失真 |
| **F** | 读心记账（只记账，不省钱） | 0 | 一行 | 无 |

### 组合起来

```
现在            每条 ~50k × 213 次 = 10.8M（占全天 59%）
A + C           每轮 −10k        → 7.6M
A + B + C       再砍长尾轮数     → 6.4M
A + B + C + D   再把结果折叠     → 4.6M（−58%）
```

## 五、优先级（我的判断）

| 顺序 | 做什么 | 为什么先它 |
|---|---|---|
| **1** | **C 说话规矩上移** | 一行代码，零风险，立刻让 2.5k 吃到 1/10 价 |
| **2** | **B replyRounds 12 → 5** | 一行，直接砍长尾 |
| **3** | **A 工具分档** | 省得最多（−8k/轮），但要加状态，得想清楚“她怎么要工具” |
| **4** | D 结果折叠 | 收益大但**有取回率风险**，必须先影子测 |
| **5** | E 历史摘要 | 顺手，收益小 |
| **6** | F 读心记账 | 只是让账准 |

**A 是唯一需要设计的一步**：给她的工具会随会话状态变。最简单的做法是——聊天默认不给手机/B站/改自己，她在回复里说“我要看看手机”时，下一轮挂上；一轮结束后自动收回。

| | 走神 | 对话 |

| 调用次数 | 242 次/天 | ~213 次/天 |

**结论**：走神已经瘦完了；**下一步的钱全在对话这条路上**，而且第一步（C）只是一行。
