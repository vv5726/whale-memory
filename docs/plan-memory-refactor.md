# 记忆重构：三类分仓 + 事件卡

> 目标：让「锚点 = 能被想起来的那件事/那个人」，而不是「文本里出现过的高频词」。
> 现状的病：小糖人挂了 431 条；捞「小糖人」排第一的是「我承认那是幻觉」。

---

## 0. 一句话原则

```
词 → 词库      人 → 人物库      事 → 记忆（事件卡 + 锚点）
```

**同一件东西只许待在一个仓里。** 这是本次重构唯一不可让步的规则。

---

## 1. 三类分仓

| 类型 | 去哪 | 存储 | 例子 |
|---|---|---|---|
| 约定 / 待办 / 决策 / 经历 / 信息 | 记忆 | `events` | A和B约定周六露营 |
| **偏好 / 禁忌** | 人物库 | `events`(kind=user) 挂 QQ 号 | C不吃香菜 |
| **梗 / 黑话 / 群规** | 词库 | `lexicon.json` | 「老地方」=南门烧烤 |
| 冲突 / 情绪 | 记忆 + `sensitivity` | `events` | A和D因迟到争执，已缓和 |

**判据（抽取时必须自问）**：

```
「想到这个词，能想起这件事吗？」
  能   → 事件锚点
  不能 → 它是词，进词库
```

---

## 2. 锚点体系（三类）

| kind | 来源 | 数量 | 权重 |
|---|---|---|---|
| `person` | 说话人 QQ 号（people 表） | 全部 | 1.0 |
| `event` | 抽取给出「这件事的主体」 | 每条 1-3 个 | 2.0 |
| `scene` | 群号 / 私聊 | 每条 1 个 | **0.5（弱信号）** |

**禁止当锚点的**：

```
✗ 泛词：人性、表情包、记忆、参数
✗ 词/梗/称呼：小糖人、抽象        → 词库
✗ 人名（人名走 person，不从文本里抽）
```

**环境锚点说明**：现在只有 3 个群，每条记忆都会挂上一个 scene 锚点，所以权重必须低，否则等于又造一批噪音。老数据无法补（`turns` 没存群号），**只对新数据生效**。

---

## 3. 事件卡字段

在 `events` 上新增（老数据留空，标 `stage='legacy'`）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `etype` | TEXT | 约定/待办/决策/经历/偏好/梗/冲突/信息 |
| `status` | TEXT | 待确认/已定/已发生/已取消/需跟进/仅记录 |
| `responsible` | TEXT | 谁该做（可空，朋友群允许无负责人） |
| `time_absolute` | TEXT | 换算后的绝对时间 |
| `time_relative` | TEXT | 原话里的相对时间（「周六下午」） |
| `place` | TEXT | 地点 |
| `evidence` | TEXT | JSON：`[{speaker, quote, msg_id}]` |
| `sensitivity` | TEXT | normal/private/high |
| `expires_at` | INTEGER | 到期时间戳（可空） |
| `memory_value` | INTEGER | 0-10，入库评分 |
| `valid_to` | INTEGER | 被哪一刻的状态更新取代（不删旧版） |

**校验规则**（后置，防模型编造）：

```
evidence 里每条的 msg_id 必须能在 turns 表里查到
查不到的 → 这条降级：confidence=low，memory_value 扣 2
```

---

## 4. 抽取变更

### 4.1 提示词

换成六元组公式 + 8 类判定 + 评分：

```
一件事 = 主体 + 事件核 + 时间锚 + 状态 + 证据 + 未来用途
标题   = 主体 + 事件核 + 时间锚
```

**硬性要求**：

```
1. 跨多条消息的同一件事必须合并；不同结果/时间/人必须拆开
2. 缺失写「待确认」，不许编造
3. 相对时间结合消息日期换算，同时保留原话
4. 每条必须有 msg_id 证据
5. 梗/称呼 → 不进事件，输出到 lexicon 字段（单独处理）
6. 偏好/禁忌 → 不进事件，输出到 person 字段（单独处理）
```

### 4.2 输出结构

```json
{
  "events":[{ "type":"约定","title":"A和B约定周六露营","people":["A","B"],
              "time":{"absolute":"2026-10-31 15:00","relative_quote":"周六下午3点"},
              "place":"南门烧烤","content":"...","status":"已定",
              "next_action":"B周六前确认帐篷","evidence":[{"speaker":"A","quote":"...","msg_id":"t_xxx"}],
              "sensitivity":"normal","expires_at":"2026-11-01","memory_value":6 }],
  "lexicon":[{ "term":"老地方","meaning":"南门烧烤","source":"上次聚会" }],
  "persons":[{ "qq":"123","note":"不吃香菜，点菜要避开" }]
}
```

**注意：一次抽取同时产出三个仓的内容**，而不是只产 events。

### 4.3 入库路由

```
events   → 事件卡（含 evidence 校验）
lexicon  → data/lexicon.json（去重合并）
persons  → events(kind=user) 挂 qq（同名覆盖）
```

---

## 5. 检索变更

```
① 状态过滤   已取消的不出
② 过期降权   expires_at 过了 → 分数 ×0.5（不删）
③ 评分参与   memory_value ≥6 加权，≤2 降权
④ 场景锚点   权重 0.5，只做加分不主导
⑤ 同组收敛   标题相似 ≥0.6 的只出最高分那条（只读，不改库）
```

**⑤ 是替代「合并去重」的方案**：库里留着全部，检索时才收敛。

---

## 6. 状态迁移（不删旧版）

```
新一条说「改到周日下午」→ 旧的「周六下午」打 valid_to，status 改『已被更新』
检索时只出有效的那条；想查「当时以为是什么」还能翻到旧的
```

---

## 7. 迁移与回滚

```
老数据   762 条：不动，标 stage='legacy'
         检索时 legacy 不加权也不降权，按现状
新数据   只有 stage='extracted' 的走新规则
回滚     每一步前复制 memory.db 到 data/backup-<原因>-<时间>.db
验收     新数据攒满 50 条后，人工看 10 条，判：像不像「一件事」
```

---

## 8. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 模型编造 evidence | 记忆不可信 | msg_id 必须存在，否则降级 |
| token 涨 2 倍 | 成本 | 只对新对话；观察一周 |
| 老数据成孤岛 | 检索割裂 | legacy 不加权，共存 |
| 状态更新漏了 | 过期事项一直提醒 | expires_at + 每日体检 |
| 三仓判定错 | 梗进事件表 | 判据写进提示词 + 抽样核对 |
| 环境锚点噪音 | 每条都挂 | 权重 0.5 |

---

## 9. 分阶段

| 阶段 | 做什么 | 是否碰数据 | 验收 |
|---|---|---|---|
| P1 | 写规则文档 + 三仓定义 | 否 | 文档可读、规则可执行 |
| P2 | 加字段（空值）+ 老数据标 legacy | 加列，不改内容 | 老数据可读可搜 |
| P3 | 新抽取提示词（三仓输出） | 只影响新数据 | 抽 10 条，人看像回事 |
| P4 | 检索接状态/评分/收敛 | 否（只读逻辑） | 同一查询对比前后 |
| P5 | 观察一周 | — | 再决定老数据 |

## 10. 自查（写完后我自己挑的毛病）

**① 8 类里「信息/通知」和「约定」边界模糊**

「报名截止 9 月 30 日」算信息还是待办？→ 需要一条：**有动作要求 → 待办；只要知道 → 信息**。

**② 偏好进人物库，会导致「今天想吃的」和「永远不吃」混在一起**

→ 偏好加 `强度` 字段（0-2）：0=随口 1=偏好 2=绝对禁忌。只在 ≥1 时长期保留。

**③ 一次抽取产三个仓，模型容易顾此失彼**

→ 分两次调用（先 events，再 lexicon+persons），成本可控、质量更稳。

**④ memory_value 由模型自评，可能全给 6 分**

→ 先跑一周看分布，若都在 5-7，就改成规则算分。

**⑤ evidence 的 msg_id 在老数据里对不上**

→ 只校验新数据；legacy 跳过校验。

**⑥ 状态迁移需要「哪条更新了哪条」的链**

→ `valid_to` 只记时间不够，还要 `superseded_by`（记新事件的 id）。
